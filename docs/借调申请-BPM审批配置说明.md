# 借调申请 - BPM 审批流程配置说明

## 流程 Key 说明

借调申请使用的 BPM 流程定义 **Key 必须为** `unified_service_launch`。

- 若出现「借调申请流程未配置」：表示系统中未找到 key 为 `unified_service_launch` 且状态为「激活」的流程
- 解决方式：
  1. 进入 **工作流程** → **流程管理**
  2. 新建流程或导入 BPMN，流程定义标识（key）必须填写 `unified_service_launch`
  3. 部署并激活该流程

## 审批链要求

借调申请审批需按以下顺序：

1. **直属领导**：被借调人所在部门的负责人（最小领导）
2. **层层审批**：沿部门树向上，每级部门负责人依次审批
3. **总经办**：审批到总经办为止

## 配置步骤

1. 登录系统，进入 **工作流程** → **流程管理**
2. 找到 **借调申请**（unified_service_launch）流程
3. 编辑流程，将审批节点配置为：
   - **第一节点**：审批人 = 被借调人（expectedExecutorId）的直属领导
     - 可通过流程变量 `expectedExecutorId` 获取被借调人
     - 审批人表达式：查询该用户所在部门的 `leader_user_id`
   - **后续节点**：审批人 = 上一级部门的负责人
     - 沿 `parent_id` 向上遍历部门树
     - 直到部门名称为「总经办」或到达根部门

4. 若 BPM 支持「多级审批」或「层级审批」模板，可直接选用并绑定上述规则

## 流程变量

发起借调时传入的变量（供审批节点使用）：

- `serviceLaunchId`：借调申请ID
- `expectedExecutorId`：被借调人ID（用于查找其直属领导）
- `executeDeptId`：借出部门ID
- `projectId`、`serviceItemId` 等业务数据

## 总经办识别

需在系统中明确总经办的定义方式，例如：

- 部门名称包含「总经办」
- 或指定部门ID
- 或为部门树的根节点
